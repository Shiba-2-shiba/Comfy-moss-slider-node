## 学習stepとレコード数

`moss_slider_node/training.py` の `record_index = step % len(prepared_records)` により、1 optimizer更新に1件を順番に使う。stepsは全レコード合計の更新数。

| 総steps | 旧18件の1件あたり使用回数 | 修正後6件の1件あたり使用回数 |
|---|---:|---:|
| 120 | 6〜7 | 20 |
| 300 | 16〜17 | 50 |
| 600 | 33〜34 | 100 |

全レコードは共通の外見方向を学ぶため、18件だから共通特徴を学ぶ総更新数まで3分の1になるわけではない。6件化は短いrunでの各条件への反復と、顔・髪の見やすい構図への集中を優先する判断。衣装・構図の多様性を減らすトレードオフがあり、十分な学習stepsや効果量は今回の画像から確定できない。LoRA未適用のpositive画像は、学習不足の証拠ではない。

## 修正内容と仮説

1. アニメ版・実写版とも6種類の普段着を各1件とし、腰上4件・太もも上まで2件へ変更。極端な長髪と顔アップ、顔アップと靴・足元の描写を競合させない。顔・髪が占める面積を優先した。
2. positiveは2本の高い青緑のツインテール、左右に1本ずつ、長さは腰までと具体化。前髪、青緑の瞳、先細りの輪郭、小さな鼻・口を全件で共有する。
3. キャラ名・作品名・実在化／コスプレの表現を本文から外す。名前から舞台装備や公式衣装が連想される経路を減らす狙い。外見特徴の記述だけで初音ミクらしさをどこまで再現できるかは未確認。
4. ユーザー指定により全roleの本文を肯定形にする。装備の除外リストは使わない。`negative` は比較元の成人女性を描く肯定形の文章で、生成用negativeとは異なる。
5. ペア内の衣装・姿勢・表情・構図・背景・光を一致させ、target／negative／neutralは同一にする。比較側は3種類の髪・瞳・輪郭を各2件に割り当てる。

1番の原因を個別に確定した実験ではない。構図競合と名前由来の装備の混入を候補とし、今回の画像で見えた問題を同時に減らすためのプロンプト改訂である。完成画像の外見一致、装備や衣装の保持、学習後の効果は保証しない。
